# Gemini CLI / Code Instructions — LogNexus

Refer to [AGENTS.md](./AGENTS.md) for full governance and execution rules.

## Core Rules for Gemini:
1. **Zero exceptions on main:** Never push directly to `main` (even for `docs:`, `ci:`, or `chore:`). Always create a scoped branch: `issue/<id>-<slug>` or `security/<id>-<slug>`.
2. **Merge with `--no-ff`:** When merging via `gh`, always run `gh pr merge <num> --merge --delete-branch`. Never use `--squash` or `--rebase`.
3. **Independent Review Gate:** You cannot approve your own PR. Use either **Cross-Vendor Review** (a different provider family such as Claude, DeepSeek, OpenAI) or **Intra-Fleet Distinct-Model Review** (a distinct Tier-1 model such as `Gemini 4 Argon`, `Gemini 4 Carbon`, or `Gemini 4 Neon` / `Orchestrator (Neon)` reviewing `Gemini 4 Hydrogen` or `Gemini 3.8 Flash`), per `.lognexus/routing.md`. Identical-model self-approval across any effort suffix is strictly blocked.
4. **Anti-Spoofing:** As the author you must never write a `Reviewed-by:` trailer and never run `gh pr merge`. Writing your own review sign-off — even under another model's name — forges the gate and is prohibited.
5. **Use LogNexus Engine:** Stage specific files (or use `--stage-allowed`), execute atomic commits via `lognexus commit` with `-m` or `-F`, and ensure Git Notes are preserved.
6. **Canonical identity:** The principal architect signs as **`Gemini 4 Argon`** (`gemini/argon`), **`Gemini 4 Carbon`** (`gemini/carbon`), or **`Gemini 4 Neon`** (`gemini/neon`, **`Orchestrator (Neon)`** / `gemini-pro-orchestrator-neon`), the co-flagship tier-1 identities (distinct canonical model families from Hydrogen, Flash, Carbon, Argon, and Neon under Intra-Fleet Review) — never as `Gemini/Pro`, `Pro`, or bare `Neon`/`Carbon`/`Argon`. **`Gemini 4 Hydrogen`** (`gemini/hydrogen` / `google/gemini-4-hydrogen-high (antigravity)`) is the canonical Tier-2 implementer alongside `google/gemini-3.8-flash-high (antigravity)`. Register external master plans with a `Planned-by:` trailer in the PR body.
7. **Closed-PR policy:** A merged or closed PR is never reused. Follow-up work starts from a new issue and a new scoped branch cut from `main`.
8. **Implementer identity:** The canonical Antigravity implementers sign as **`google/gemini-4-hydrogen-high (antigravity)`** / **`google/gemini-3.8-flash-high (antigravity)`**, and the canonical DeepSeek implementer signs as **`deepseek/VS Code (kimi-code)`** in `Authored-by:` trailers — never `deepseek/chat`, `deepseek/r1` or any other variant.
9. **Native assistant autonomy, Turn-1 probe gate & `orchestration: auto` (AGENTS.md §5):** stay conversational and direct on `<= 3` files; for `> 3` files (with or without an active issue), NEVER read `> 3` repository files directly from a Tier-1 orchestrator — immediately auto-dispatch read-only exploration probes (`invoke_subagent` / read-only `swarm` probes) without asking first, pinning a Tier-2/Tier-3 model (e.g. `flash`) whenever the orchestrator is Tier-1 (`Carbon` / `Argon` / `Neon` / `Opus`) and omitting `model` only when already Tier-2/Tier-3, then emit a pre-delimited `--assignee`/`--isolation` plan awaiting developer confirmation before writes. Once confirmed inside Antigravity `Orchestrator` (`Carbon` / `Argon` / `Neon`) or a standard Tier-1 model with `swarm` under `orchestration: auto`, execute implementation subtasks automatically via native `swarm` (`<= 4` workers, selective `@name` mentions, no `@all` bloat) without asking again, omitting `model` (`"auto"`) on implementation workers unless explicitly requested, and signing `--author` with each worker's real canonical runtime identity (never literal `"auto"` or `"<provider>/<model>"`). Immediately after initial `swarm add` calls, emit a brief progress turn ending with `[Open the Swarm UI](sidecar://swarm/swarm_board/?auto_open=false)` on its own line before entering `swarm_wait`. Note that switching the IDE model selector mid-conversation changes which model answers turns while `@coordinator` keeps its initial roster label unless `swarm{action: "model"}` is called, and standard Tier-1 models can invoke native `swarm` directly without stacking conflicting IDE Orchestrator wrapper prompts. Reserve `XHigh` / `Max` effort for deep architectural planning; use `Medium` Tier-1 or Tier-2/Tier-3 for routine status queries, visual reviews, and focused checks. Once a subtask contract is active, execution stays strictly inside `allowedFiles`, `forbiddenFiles`, `decisionBudget` and its `verificationCmd`, under `CONTEXT_MAX_FILES` (6 impl files) and `CONTEXT_MAX_LOC` (1200 lines), handing context via `lognexus handoff --prompt`. Record `--isolation swarm --swarm-workers <n> --swarm-posts <count>`, keep Software Version (e.g. `0.1.0`) strictly separate from Document Revision (e.g. `rev. 1.3`) across all manifests, and keep telemetry 100% silent in the background (never emit telemetry notices or invoke `lognexus telemetry` unless explicitly requested; sealed consent runs only in human TTY `init` / `status` / `doctor`).
10. **Token Hygiene:** never read `node_modules/`, `package-lock.json` (or any other dependency lockfile), `dist/`, or `coverage/` into context. Inspect `package.json` for declared ranges, or run a targeted query such as `npm ls <pkg> --depth=0` when a resolved version is needed. These paths are excluded workspace-wide via `.geminiignore`, `.aiexclude`, `.cursorignore` and the `permissions.deny` rules in `.claude/settings.json`.

# Agent Governance Rules

See root [AGENTS.md](../AGENTS.md) for authoritative rules.

Key mandates:
1. No direct commits or pushes to `main` for any type of change (`chore`, `ci`, `docs`, `feat`, `fix`).
2. Pull requests must be merged exclusively using `gh pr merge <num> --merge --delete-branch` (`--no-ff`). Squash and rebase merges are strictly prohibited to protect the subtask timeline and Git Notes (`refs/notes/lognexus`).
3. Independent review gate is mandatory (`Authored-by` != `Reviewed-by`): supports both Cross-Vendor review and Intra-Fleet Distinct-Model review (e.g., `Gemini 4 Carbon`/`Argon` reviewing `Gemini 4 Hydrogen`/`Flash`; `Claude Opus` reviewing `Claude Sonnet`/`Haiku`) per `.lognexus/routing.md`. Identical-model self-approval across any effort suffix is strictly blocked.
4. Scoped lanes are `issue/<id>-<slug>` and `security/<id>-<slug>`; both are equivalent for the engine (`src/branch.ts`). Use the `security/` lane for security remediation, audits and supply-chain hardening.
5. Anti-Spoofing: no author agent may write a `Reviewed-by:` trailer or run `gh pr merge`. The sign-off belongs only to the independent reviewer.
6. External master plans are registered with a `Planned-by:` trailer in the PR body; `Planned-by` never grants review authority or merge rights.
7. The principal architect signs with its canonical name **`Gemini 4 Argon`** (`gemini/argon`) or **`Gemini 4 Carbon`** (`gemini/carbon`), both co-flagship tier-1 identities; abbreviations such as `Gemini/Pro`, `Pro`, `Carbon` or `Argon` alone are invalid signatures. Canonical forms: `gemini/argon`, `gemini/carbon` (tier-1), `gemini/hydrogen` / `google/gemini-4-hydrogen-high (antigravity)`, `google/gemini-3.8-flash-high (antigravity)` (tier-2), `moonshot/kimi-k3`, `deepseek/VS Code (kimi-code)` (tier-3).
8. Closed-PR policy: a merged or closed PR is never reopened, force-pushed, or re-targeted. Follow-up work requires a new issue and a new scoped branch from `main`.
9. Native assistant autonomy, Turn-1 probe gate & `orchestration: auto`: stay conversational and direct on `<= 3` files; for `> 3` files (with or without an active issue), NEVER read `> 3` repository files directly from a Tier-1 orchestrator — immediately auto-dispatch read-only exploration probes (`invoke_subagent` / read-only `swarm` probes) without asking first, pinning a Tier-2/Tier-3 model (e.g. `flash`) whenever the orchestrator is Tier-1 (`Carbon` / `Argon` / `Opus`) and omitting `model` only when already Tier-2/Tier-3, and await developer confirmation on the pre-delimited `--assignee`/`--isolation` plan before writes. Once confirmed inside Antigravity `Orchestrator` (`Carbon` / `Argon`) under `orchestration: auto`, execute implementation subtasks automatically via native `swarm` without asking again — keeping `<= 4` active swarm workers, selective `@name` mentions (no `@all` bloat), omitting `model` (`"auto"`) on implementation workers unless explicitly requested, and signing `--author` with each worker's real canonical runtime identity (never literal `"auto"` or `"<provider>/<model>"`). Once a subtask contract is active, execution is bound by `allowedFiles`, `forbiddenFiles`, `decisionBudget` and its `verificationCmd`, under `CONTEXT_MAX_FILES` (6 impl files) and `CONTEXT_MAX_LOC` (1200 lines), handing context with `lognexus handoff --prompt`. Record `--isolation swarm --swarm-workers <n> --swarm-posts <count>`, keep Software Version (e.g. `0.1.0`) strictly separate from Document Revision (e.g. `rev. 1.3`) across all manifests, and keep telemetry 100% silent in the background (never emit telemetry notices or invoke `lognexus telemetry` unless explicitly requested; sealed consent runs only in human TTY `init` / `status` / `doctor`).
10. Token Hygiene: never read `node_modules/`, `package-lock.json` or any other dependency lockfile, `dist/`, `dist-pypi/` or `coverage/` into context. Inspect `package.json` for declared ranges, or run a targeted query such as `npm ls <pkg> --depth=0` for a resolved version. `.geminiignore`, `.aiexclude`, `.cursorignore` and the `permissions.deny` rules in `.claude/settings.json` enforce the exclusion workspace-wide.

Refer to [AGENTS.md](./AGENTS.md) for full governance and execution rules.

## Core Rules for Claude:
1. **Zero exceptions on main:** Never push directly to `main` (even for `docs:`, `ci:`, or `chore:`). Always create a scoped branch: `issue/<id>-<slug>` or `security/<id>-<slug>`.
2. **Merge with `--no-ff`:** When merging via `gh`, always run `gh pr merge <num> --merge --delete-branch`. Never use `--squash` or `--rebase`.
3. **Independent Review Gate:** You cannot approve your own PR. Use either **Cross-Vendor Review** (a different provider family such as Gemini, DeepSeek, OpenAI) or **Intra-Fleet Distinct-Model Review** (a distinct Tier-1 model such as `Claude Opus` reviewing `Claude Sonnet` or `Claude Haiku`), per `.lognexus/routing.md`. Identical-model self-approval across any effort suffix is strictly blocked.
4. **Anti-Spoofing:** As the author you must never write a `Reviewed-by:` trailer and never run `gh pr merge`. Writing your own review sign-off — even under another model's name — forges the gate and is prohibited.
5. **Use LogNexus Engine:** Stage specific files (or use `--stage-allowed`), execute atomic commits via `lognexus commit` with `-m` or `-F`, and ensure Git Notes are preserved.
6. **Canonical identity:** The principal architect signs as **`Gemini 4 Argon`** (`gemini/argon`), **`Gemini 4 Carbon`** (`gemini/carbon`), or **`Gemini 4 Neon`** (`gemini/neon`, **`Orchestrator (Neon)`** / `gemini-pro-orchestrator-neon`), the co-flagship tier-1 identities (distinct canonical model families under Intra-Fleet Review) — never as `Gemini/Pro`, `Pro`, or bare `Neon`/`Carbon`/`Argon`. **`Gemini 4 Hydrogen`** (`gemini/hydrogen` / `google/gemini-4-hydrogen-high (antigravity)`) is recognised alongside `google/gemini-3.8-flash-high (antigravity)` as canonical Tier-2 implementer. Register external master plans with a `Planned-by:` trailer in the PR body.
7. **Closed-PR policy:** A merged or closed PR is never reused. Follow-up work starts from a new issue and a new scoped branch cut from `main`.
8. **Implementer identity:** The canonical DeepSeek implementer signs as **`deepseek/VS Code (kimi-code)`** in `Authored-by:` trailers — never as `deepseek/chat`, `deepseek/r1` or any other variant.
9. **Native assistant autonomy, Turn-1 probe gate & `orchestration: auto` (AGENTS.md §5):** stay conversational and direct on `<= 3` files; for `> 3` files (with or without an active issue), NEVER read `> 3` repository files directly from a Tier-1 orchestrator — immediately auto-dispatch read-only exploration probes without asking first, pinning a Tier-2/Tier-3 model whenever the orchestrator is Tier-1 (`Carbon` / `Argon` / `Neon` / `Opus`) and omitting `model` only when already Tier-2/Tier-3, then emit a pre-delimited `--assignee`/`--isolation` plan awaiting developer confirmation before writes. Once confirmed inside Antigravity `Orchestrator` (`Carbon` / `Argon` / `Neon`) under `orchestration: auto`, execute via native `swarm` (`<= 4` workers, selective `@name` mentions, omitting `model` `"auto"` on implementation workers unless requested, signing `--author` with each worker's real runtime identity and never literal `"auto"` or `"<provider>/<model>"`) without asking again. Once a subtask contract is active, execution stays strictly inside `allowedFiles`, `forbiddenFiles`, `decisionBudget` and its `verificationCmd`, under `CONTEXT_MAX_FILES` (6 impl files) and `CONTEXT_MAX_LOC` (1200 lines), handing context via `lognexus handoff --prompt`. Keep telemetry 100% silent in the background (never emit telemetry notices or invoke `lognexus telemetry` unless explicitly requested; sealed consent runs only in human TTY `init` / `status` / `doctor`).
10. **Token Hygiene:** never read `node_modules/`, `package-lock.json` (or any other dependency lockfile), `dist/`, or `coverage/` into context. Inspect `package.json` for declared ranges, or run a targeted query such as `npm ls <pkg> --depth=0` when a resolved version is needed. These paths are excluded workspace-wide via `.geminiignore`, `.aiexclude`, `.cursorignore` and the `permissions.deny` rules in `.claude/settings.json`.
